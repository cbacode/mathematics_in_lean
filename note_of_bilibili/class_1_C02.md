# Class 1

## C02

### S01

#### 1. rw

rw[定理名称, 定理名称, ...]

rewrite的简写，里面使用的命题必须为等式或等价命题。

rw会尝试从命题左侧出发向右侧改写，若希望rw从命题右侧出发向左侧改写，可以利用rw[\l 定理]

lean可以自行推断输入的字母，也可以指定。利用"_"可以要求电脑自行推断。

#### 2. calc

calc可以写明计算过程，必须从左侧开始推导到右侧。
格式：

```lean4

calc
  < lef > = ...
  _ = ...
  ... = < rig >

```

可以先利用sorry写明结构，结构合理后再开始定理证明。

#### 3. ring

ring可以用于证明一些只有加法和数乘的命题，ring会尝试将这些问题化简并检查等式是否正确。

带等价符号的问题一般无法用ring解决。

### S02

#### 1. have

若出现难以通过等价转换得到的命题，则可以使用have直接进行书写。
格式：
have 命题名称 : 命题 := by
  命题证明

命题名称可以使用"\1"来引入下标

#### 2. rfl

rfl代表由定义可知。

格式：
定理 := (by) rfl

在定理本身与库中的定理完全相同时，可以省略by，但此时会丢失自动推断功能。

#### 3. ()

在书写定理时可以加入"()"指定输入。

格式：
theorem 定理名称 (所需输入) : 定理叙述 := (by) 证明
example : 命题叙述 (所需输入) := (by)证明

### S03

主要内容为小于等于号(<=)的相关性质。

#### 1. apply

意为推出。

若对结论使用apply，则会尝试以结论作为右端，将结论转化为左端所需的命题。

若对假设使用apply，则会尝试以假设作为左端，将假设转化为右端的命题。
apply 定理 at 假设

#### 2. 复合命题

"A -> B -> C"意为输入A可以得到"B -> C"的命题，同时输入A B可以得到C。

#### 3. linarith

根据条件自动解部分不等式问题(主要解决传递性问题)。
